## 4. 红线（违反即返工）

1. **不换技术栈**：外壳 Electron，渲染 three.js + @pixiv/three-vrm，动画自研姿态引擎。不要"顺手"引入 Unity/Godot/Tauri。
2. **不引入任何人工内容生产**：不外包、不动捕、不找美术、不拍摄。
3. **MVP-0 不碰 GPU**：不训练、不调用生成 API、不租算力。
4. **LLM 只能输出枚举意图**，永远不直接驱动骨骼（PRD §8.4）。
5. **不扩范围**：PRD §4.2「非目标」一条都不做（多角色、移动端、语音唤醒、动作编辑器……）。

---

## 5. 第一件事（Day 1–2）

搭骨架，只验证两件事——**透明**和**穿透**。

```bash
pnpm create @quick-start/electron
pnpm add three @pixiv/three-vrm zod
pnpm dev
```

| 验收 | 标准 |
| --- | --- |
| S1 透明 | 静态 / 动态 / 纯色三种壁纸下均无黑边、无白边 |
| S2 穿透 | 鼠标在方块上可点击，移开后能点到下层窗口；切换无"粘住" |
| 性能 | 空闲 GPU < 8%，内存 < 400 MB |

**任何一条不过，停下来找用户改方案，不要继续写动画引擎**（TDD §15)。

## 7. 会浪费时间的坑（都是已踩过的）

| 坑 | 正确做法 | 出处 |
| --- | --- | --- |
| 直接把四元数写到骨骼节点 | 必须写 **normalized bone**（`getNormalizedBoneNode`），否则动作扭曲/反向 | TDD §6.1 |
| 用 `-webkit-app-region: drag` 拖拽 | 透明 + 穿透下失效，手写拖拽 | TDD §5.3 |
| 用 `readPixels` 做点击命中 | 打断 GPU 管线；用射线打简化碰撞体 | TDD §5.2 |
| 每次 mousemove 都发 IPC | 只在命中状态变化时发 | TDD §5.2 |
| 先做 14 个动作再调手感 | 先做 1 个跑通全链路，再铺量 | TDD §3.3 / 风险 T2 |
| 用 `AnimationMixer` 做分层 | 没有骨骼遮罩、打断会回弹；用自研引擎 | TDD §3.3 |
| 图生 3D 做角色 | 没有 BlendShape = 没有表情；MVP-0 用 VRoid | TDD §3.4 |
| 把"萌不萌"交给 VLM 判 | VLM 只能判崩坏与一致性，判不了萌 | TDD §13.5 |

## 8. 测试怎么做（只有一个人）

- 提交前：`pnpm test`（L1 单元 + L2 无头引擎）
- 每日：视觉回归截图 diff
- 每周：8 小时浸泡
- 发版前：15 分钟人工清单（TDD §13.4）

**自测最大的风险不是漏测，是自欺**：录屏后隔 48 小时再看，只看录屏不看实时画面（TDD §13.6）。
