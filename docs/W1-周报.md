## 三、阻塞：Electron 在本机启动即崩溃（环境问题，非代码问题）

**现象**：任何 stock Electron（44.9.3 / 44.0.0 / 40.10.6，含 `--no-sandbox` `--disable-gpu` `--single-process` 等全部标志组合）在本机启动即退出，Windows 事件日志报 **0xC0000005（访问违例）**，崩溃模块为 `electron.exe` 自身。

**根因**：WER 崩溃报告 `LoadedModule` 里出现

```
C:\ProgramData\A-Volute\A-Volute.Nahimic\Modules\Scheduled\x64\AudioDevProps2.dll
```

本机安装了 **Nahimic（A-Volute）音频增强软件**，其计划任务 `NahimicTask32` / `NahimicTask64`（均 Running）+ 服务 `NahimicService` 会向进程注入上述 DLL——这是公认会导致 Chromium/Electron 崩溃的冲突。对比：正在正常运行的 DSH 客户端是「改造版 Electron + 改名进程」，未加载任何 Nahimic DLL，因此幸免。

**验证过程**：换版本（40/44）、换启动方式（直接/计划任务剥离进程树）、加各种 GPU/沙箱规避参数，均崩溃；而经典 Win32 的 `winver` 可正常弹窗——确认不是通用 GUI 限制，而是 Nahimic 注入触发。

**解决方式（二选一，需管理员权限，我当前为非管理员无法代做）**：

```powershell
# A. 停用注入源（可逆）
Disable-ScheduledTask -TaskName "NahimicTask32","NahimicTask64"
Stop-Service NahimicService; Set-Service NahimicService -StartupType Disabled
# B. 或直接卸载 Nahimic（设置 → 应用）
```

之后 `cd desktop-pet && pnpm dev` 即可验证 S1/S2。

## 更新（排查后修正）

> 上文「三、阻塞」曾把根因归为 Nahimic，**现已修正**：

- Nahimic 确实在向进程注入 `AudioDevProps2.dll`（已知 Chromium 崩溃源），但停用其服务/注入后崩溃依旧——它只是帮凶。
- 最终根因：本机 stock Chromium 的 **GPU 虚拟化上下文创建失败**（日志 `Failed to create shared context for virtualization`），导致 0xC0000005 / 0x80000003 崩溃。已逐一排除：Nahimic、GameViewer 虚拟显示器、Electron 版本（40/44）、进程树、缓存、各类 GPU/沙箱参数。仅 DeepSeek 自研改造版 Electron 能在这台机器正常跑。
- 这是**机器级环境问题**（Lenovo 双显卡 + 虚拟显示器组合），非代码问题，普通用户机器不受影响。
- S1/S2 需在干净的 Windows 机器上跑 `pnpm dev` 验收。本轮对系统的改动（Nahimic 服务、GameViewer 显示器）**已全部还原**。
- 已预留 `scripts/fix-nahimic.ps1`（停用 Nahimic 注入、保留其音频 EQ），但请注意它解决不了本机的 GPU 虚拟化崩溃。
